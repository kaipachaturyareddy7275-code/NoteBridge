
# NoteBridge - Database Design

## 1. Database Overview

- Project Name: NoteBridge
- Database Name: notebridge.db
- Database Type: SQLite

SQLite is used to store and manage document information, user questions, and AI-generated answers.

## 2. Database Tables

### Table 1: Documents

Stores information about uploaded PDF documents.

| Field Name | Data Type | Description |
|---|---|---|
| id | INTEGER | Unique document ID (Primary Key) |
| filename | TEXT | Name of the uploaded PDF |
| file_path | TEXT | Location of the PDF file |
| upload_date | TEXT | Date and time of upload |

### Table 2: Questions

Stores questions asked by users about uploaded documents.

| Field Name | Data Type | Description |
|---|---|---|
| id | INTEGER | Unique question ID (Primary Key) |
| document_id | INTEGER | References the document ID (Foreign Key) |
| question | TEXT | Question asked by the user |
| created_at | TEXT | Date and time of the question |

### Table 3: Answers

Stores answers generated by the application.

| Field Name | Data Type | Description |
|---|---|---|
| id | INTEGER | Unique answer ID (Primary Key) |
| question_id | INTEGER | References the question ID (Foreign Key) |
| answer | TEXT | Answer generated by the application |
| created_at | TEXT | Date and time of the answer |

## 3. Table Relationships

- One document can have multiple questions.
- Each question belongs to one document.
- Each question has one answer in the initial design.
- Each answer belongs to one question.

## 4. Primary and Foreign Keys

- Documents: `id` is the Primary Key.
- Questions: `id` is the Primary Key and `document_id` is the Foreign Key.
- Answers: `id` is the Primary Key and `question_id` is the Foreign Key.

## 5. Database Operations (CRUD)

The application will support the following operations:

- Create: Store uploaded document information.
- Read: Retrieve stored document information.
- Update: Modify document information when required.
- Delete: Remove document information when a document is deleted.
